# CLI reference

Generated by `scripts/gen-cli-reference.py` from `mysh help --json`; do not edit by hand. See the other guide pages for what the commands mean and how they fit together.

## Shared connection options

Every command that takes a `HOST` accepts these (shown once here, elided from the tables below):

| option | meaning |
| --- | --- |
| `-v, --verbose` | Increase log verbosity; `-vv` includes handshake and stream events |
| `-p, --port <PORT>` | Port (default 7722, or from `HOST:PORT`) |
| `-i, --identity <PATH>` | Identity: a private key file, or a `.pub` naming an ssh-agent key (see docs/02-security.md for the resolution order) |
| `--pin <KEY>` | Expected server public key or fingerprint |
| `--accept-new` | Trust unknown server keys without asking (TOFU: accept new) |
| `--strict` | Fail when the server key is unknown (TOFU: strict) |
| `-s, --shell` | Run `shell` on connect; exit when the last session ends |
| `-t, --force-pty` | Force a PTY for CMD |
| `-T, --no-pty` | Forbid a PTY for CMD |
| `-N, --no-session` | No session and no stdin; forwards only (safe to run with `&`) |
| `--attach <ID>` | Reattach a detached session (`--attach` picks the only one, `--attach=ID` a specific one) instead of opening a new one |
| `-L, --local <SPEC> (repeatable)` | Local forward `[bind:]port:host:hostport` (repeatable) |
| `-R, --remote <SPEC> (repeatable)` | Remote forward `[bind:]port:host:hostport` (repeatable) |
| `-D, --dynamic <SPEC> (repeatable)` | Dynamic (SOCKS) forward `[bind:]port` (repeatable) |
| `-e, --escape <KEY|NONE>` | Meta key: a single character, caret notation (`^]`), or `none` |
| `-q, --quiet` | No connect banner |
| `--env <NAME[=VALUE]> (repeatable)` | Send an environment variable (repeatable; the server must accept it) |
| `--baked-only` | Ignore key files on disk; use only the compiled-in identity and peers |
| `--no-ctl` | Do not reuse a running interactive client's control socket for `put`/`get`/`forward`/`authorize`; always open a new connection |
| `--json` | One JSON document per command on stdout; errors as JSON on stderr (docs/05-meta-shell.md "Agent interface") |
| `--json-stream` | Newline-delimited JSON events on stdout as they happen |
| `--plain` | No ANSI sequences, progress lines, banner or prompt redraws (implied by `--json`, `--json-stream`, and when stdout is not a terminal) |
| `--timeout <DURATION>` | Give up after DURATION (`10s`, `2m`, `500ms`): a command gets TERM, then KILL after 2 s; exit code 124 |
| `--cwd <DIR>` | Working directory for CMD (`~`-relative paths are expanded by the server) |
| `--master <NEVER|AUTO|ALWAYS>` | Start a background master when no control socket is there (`never` by default; `[defaults] master` in the config file) |
| `--hosts <HOST,...> (repeatable)` | Fan out to these hosts (comma-separated, repeatable; `run`, `put` and `get` only) |
| `--group <NAME> (repeatable)` | Fan out to a `[groups.NAME]` of the config file (repeatable; `run`, `put` and `get` only) |

## `mysh HOST [CMD...]`

Bare form: `mysh HOST` lands at the meta prompt; `mysh HOST CMD...` runs `CMD` remotely and exits with its status. `HOST` is `host`, `host:port`, `[v6]:port`, a config alias, or `@NAME` for a connection accepted by `mysh accept`.

## `mysh connect`

Connect to HOST (same as the bare form; use when HOST collides with a subcommand name)

`mysh connect [OPTIONS] [HOST] [CMD]...`

| option | meaning |
| --- | --- |
| `-M` | Run as a background master for HOST: serve the control socket, no prompt, no stdin (same as `mysh master HOST`) |
| `[HOST]` | `host`, `host:port`, `[v6addr]:port`, bare `v6addr`, or a config alias |
| `[CMD]...` | Command to run remotely instead of landing at the prompt |

## `mysh serve`

Run the server

`mysh serve [OPTIONS]`

| option | meaning |
| --- | --- |
| `--listen <ADDR> (repeatable)` | Listen address (repeatable; default `[::]:7722`, falling back to `0.0.0.0:7722`) |
| `--key <PATH>` | Host identity key file |
| `--no-generate-key` | Fail instead of generating a host key on first start |
| `--authorized-keys <PATH> (repeatable)` | Additional `authorized_keys` file (repeatable) |
| `--authorized-key <KEY> (repeatable)` | Additional authorized public key line (repeatable) |
| `--no-ssh-authorized-keys` | Do not read `~/.ssh/authorized_keys` |
| `--shell <PATH>` | Override shell resolution for sessions |
| `--accept-env <NAME> (repeatable)` | Extra environment variable names accepted from clients (repeatable) |
| `--deny <FEATURE> (repeatable)` | Disable a feature (repeatable) |
| `--name <NAME>` | Name sent in the server hello (default: hostname) |
| `--baked-only` | Ignore key files on disk; use only the compiled-in identity and peers |
| `--handshake-rate <N>` | Handshakes accepted per minute from one client address (0 = no limit) |
| `--idle-timeout <SECS>` | Close a connection with no control traffic for this many seconds |
| `--detach-grace <SECS>` | Keep a detached PTY session alive for this many seconds |
| `--no-signature-auth` | Do not accept ssh-ed25519 signature authentication |
| `--pair <DURATION>` | Open a pairing window at start (default 5m) and print its one-time code; `SIGUSR1` opens another at any time |
| `--audit <PATH>` | Append one JSON line per audited event to PATH (`-`: stderr); see docs/02-security.md "Audit log" |
| `--connect-back <ADDR> (repeatable)` | Connect back to a client that accepts connections (`mysh accept`) at ADDR (`host[:port]`, default port 7722; repeatable). Without `--listen` nothing is bound |
| `--connect-period <DURATION>` | Time from the start of one connect-back attempt to the start of the next (default `5m`) |
| `--connect-jitter <PERCENT>` | Spread each connect-back period by ± this percentage (default 10) |
| `--connect-max <DURATION>` | Close a connect-back connection the client has held for this long (default `30m`) |
| `--allow-bind-request` | Let authorized clients ask the server to bind a listener (`ControlMsg::Bind`, the client's `bind` command) |
| `--daemon` | Detach: re-run in the background (own process group, no terminal) and exit 0 once it is up; `--log` and `--pid-file` say where it writes. Prefer a service unit from `contrib/` where one exists |
| `--log <PATH>` | With `--daemon`: append the log to PATH (default `$XDG_STATE_HOME/mysh/<command>.log`) |
| `--pid-file <PATH>` | Write the process id to PATH once up (removed on exit); with `--daemon` or without |
| `-v, --verbose` | Increase log verbosity; `-vv` includes handshake and stream events |
